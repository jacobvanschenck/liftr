# Liftr

[![CI](https://github.com/jacobvanschenck/liftr/actions/workflows/ci.yml/badge.svg)](https://github.com/jacobvanschenck/liftr/actions/workflows/ci.yml)

A private strength-training log for a small household. The phone-first UI is built for the gym:
start a routine, log sets, and see the same history on the dashboard and each exercise.

Live app: **https://liftr.jacobvs.workers.dev**

## Stack

- **Astro 7** server-rendered pages on **Cloudflare Workers**
- **htmx 4** for server mutations and HTML fragments
- **Alpine.js 3** for local UI state (plate math, steppers, builders)
- **Cloudflare D1** (SQLite) with raw SQL and typed helpers
- **Clerk** for sign-in, reusing the existing Liftr development instance
- Installable PWA, online-only, free `*.workers.dev` hostname

No React Native, Expo, Convex, ORM, or paid Cloudflare features.

## Local development

```sh
pnpm install
pnpm cf-typegen
pnpm dev
```

The app runs at `http://localhost:4321`. Use `pnpm astro dev stop` to stop the background dev
server. `worker-configuration.d.ts` is generated by `pnpm cf-typegen` and is gitignored because it
can embed literal values from `.dev.vars`; run it before `pnpm check` on a fresh clone.

### Authentication locally

Local sign-in uses Clerk normally. For quick QA there is a dev-only bypass in
`src/middleware.ts`:

1. Put `DEV_AUTH_BYPASS=1` in `.dev.vars`.
2. Get a member id from the local database:
   ```sh
   pnpm wrangler d1 execute liftr --local --command "SELECT id, name FROM members"
   ```
3. Set the `liftr_dev_member` cookie to that member id and open `http://localhost:4321/`.

Never set `DEV_AUTH_BYPASS` in production (it is not in `wrangler.jsonc`).

`.dev.vars` and `.env.local` are gitignored. They must contain:

```dotenv
CLERK_SECRET_KEY=sk_test_...
PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_...
ALLOWED_CLERK_USER_IDS=user_...,user_...
DEV_AUTH_BYPASS=1
```

`ALLOWED_CLERK_USER_IDS` is a comma-separated list of Clerk user ids that may be provisioned as
family members.

## Database

```sh
pnpm db:migrate:local    # apply migrations to local D1
pnpm db:migrate:remote   # apply migrations to production D1
```

- `migrations/0001_init.sql` — schema and indexes
- `migrations/0002_import.sql` — private, local-only Convex import (members, exercises, routines, history)
- `scripts/import-convex.mjs` — private, local-only generator for that import

Local D1 state lives under `.wrangler/` and is gitignored. To reset local data, stop the dev
server, delete `.wrangler/state/v3/d1`, and rerun `pnpm db:migrate:local`.

### Private data

This public repository is a sanitized copy of a personal app. The production import data is
intentionally not committed. These files stay local and are gitignored:

- `migrations/0002_import.sql` — personal member and workout history
- `scripts/import-convex.mjs` — regenerates the import from a private Convex export
- `PLAN.md` — internal project notes
- `worker-configuration.d.ts` — generated, may contain literal local env values

A fresh clone applies `migrations/0001_init.sql` only. To restore personal history, put the private
import file in `migrations/` locally and run the migration command. The live database is unaffected.

## Deploy

```sh
pnpm cf-typegen          # after changing wrangler.jsonc
pnpm check
pnpm build
pnpm run deploy          # astro build && wrangler deploy
```

`pnpm deploy` is reserved by pnpm itself; use `pnpm run deploy`.

Before the first deploy, apply migrations and set the Worker secrets:

```sh
pnpm db:migrate:remote
pnpm wrangler secret put CLERK_SECRET_KEY
pnpm wrangler secret put ALLOWED_CLERK_USER_IDS
```

`ALLOWED_CLERK_USER_IDS` is a secret rather than a `wrangler.jsonc` var so that real Clerk user
ids are not committed. Separate the ids with commas.

The Worker name is `liftr`. Keep it stable: changing the `workers.dev` origin would force a PWA
reinstall. The production origin is also allowlisted in the existing Clerk development instance.

## PWA notes

- `public/manifest.webmanifest` — name, icons, standalone display, theme
- `public/sw.js` — caches only static assets and the offline page
- HTML navigations and `/api/*` are never cached, so Clerk redirects cannot go stale
- `public/offline.html` is the offline fallback
- Install on iPhone with **Share → Add to Home Screen**

The service worker only registers on HTTPS. Bump `CACHE` in `public/sw.js` when changing cached
static assets.


## Behavior worth knowing

- One in-progress session per member. The routines page shows a resume card.
- New sets require reps 1–1000 and a positive load. Imported bodyweight sets with load 0 are
  preserved for history parity.
- Completing a session requires at least one set; discarding removes it and its sets.
- The dashboard score uses each core lift's **most recent** performance, not its all-time best.
- Routines are family-shared; sessions and body values belong to one member.
- The app is online-only. The offline page explains that sets cannot be saved without a
  connection.
